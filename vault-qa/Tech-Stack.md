> Source of truth for the current stack. Everything below is read from `frontend/package.json`, `next.config.ts`, `pnpm-workspace.yaml`, and `tsconfig.json` — none of it is a deliberate architectural decision, it's `create-next-app` defaults. No ADR exists for the stack; open one ([[Project-Status]] → Next) if and when a real choice replaces a default.

## Repository layout
```
/LICENSE          MIT
/frontend/        the only application code — a Next.js App Router project
```
No backend, no database, no CI config, no tests, and no `.env.example` exist in the repo.

## Stack
- **Framework:** Next.js 16.3.4, App Router (`frontend/src/app/`)
- **UI:** React 19.2.8 / react-dom 19.2.8
- **Language:** TypeScript 5 (`frontend/tsconfig.json`)
- **Styling:** Tailwind CSS 4 via `@tailwindcss/postcss`
- **Fonts:** Geist / Geist Mono via `next/font/google`
- **Lint:** ESLint 9 + `eslint-config-next`
- **Package manager:** pnpm 11.15.1 (`packageManager` field), workspace at `frontend/pnpm-workspace.yaml` with `sharp` and `unrs-resolver` native builds disabled (`allowBuilds`)
- **React Compiler:** enabled (`reactCompiler: true` in `next.config.ts`, `babel-plugin-react-compiler` dependency)

## Working with this codebase
`frontend/AGENTS.md` (imported by `frontend/CLAUDE.md`) states this Next.js version has breaking changes from what a model's training data expects — APIs, conventions, and file structure may differ. It instructs reading `node_modules/next/dist/docs/` before writing code, and to heed deprecation notices. That file is regenerated by `next dev`; committing it alongside real work keeps the tree clean.
